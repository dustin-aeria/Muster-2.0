## 1. Purpose

This document provides a standardized template and process for conducting After Action Reviews (AARs) following projects, significant operations, incidents, or exercises. AARs are a structured method for capturing lessons learned, identifying improvements, and promoting organizational learning.

---

## 2. Scope

AARs should be conducted after:
- Significant projects (new client, new operation type, complex mission)
- Safety incidents and near misses
- Emergency response activations
- Training exercises and drills
- Operations with unusual challenges
- Client complaints or issues
- Any event with significant learning potential

---

## 3. AAR Process Overview

### 3.1 AAR Principles

| Principle | Description |
|:----------|:------------|
| **Timely** | Conduct as soon as practical after the event (ideally within 48-72 hours) |
| **Honest** | Open, candid discussion without blame |
| **Inclusive** | All participants contribute |
| **Focused** | Concentrate on learning and improvement |
| **Action-Oriented** | Identify specific actions to implement lessons |
| **Documented** | Capture findings in writing |

### 3.2 AAR Steps

```
┌─────────────────────────────────────────────────────────┐
│  STEP 1: PREPARE                                        │
│  - Schedule AAR session                                 │
│  - Gather relevant documentation                        │
│  - Identify participants                                │
│  - Prepare AAR template                                 │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│  STEP 2: CONDUCT                                        │
│  - Review what was planned                              │
│  - Discuss what actually happened                       │
│  - Identify what went well                              │
│  - Identify what could improve                          │
│  - Capture lessons and actions                          │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│  STEP 3: DOCUMENT                                       │
│  - Complete AAR template                                │
│  - Assign action owners and due dates                   │
│  - Distribute to participants                           │
│  - File in project/event records                        │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│  STEP 4: FOLLOW UP                                      │
│  - Track action completion                              │
│  - Verify implementation                                │
│  - Transfer lessons to lessons learned register         │
│  - Update procedures if required                        │
└─────────────────────────────────────────────────────────┘
```

## 4. AAR Facilitation

### 4.1 Facilitator Role

- Creates a safe environment for honest discussion
- Keeps discussion focused and productive
- Ensures all participants contribute
- Captures key points accurately
- Avoids assigning blame
- Drives toward actionable outcomes

### 4.2 Facilitator Guidelines

| Do | Do Not |
|:---|:-------|
| Ask open-ended questions | Ask leading questions |
| Listen actively | Dominate the discussion |
| Remain neutral | Take sides |
| Focus on process and systems | Focus on individuals |
| Encourage diverse perspectives | Allow one person to dominate |
| Document accurately | Editorialize or interpret |

### 4.3 Sample Facilitation Questions

**What Was Planned:**
- What were the objectives?
- What was the plan to achieve them?
- What did we expect to happen?

**What Actually Happened:**
- What actually occurred?
- What was the sequence of events?
- What was the outcome?

**What Went Well:**
- What worked as planned or better?
- What should we repeat?
- What practices should we standardize?

**What Could Improve:**
- What did not go as planned?
- What challenges did we face?
- What would we do differently?

**Root Causes:**
- Why did things happen the way they did?
- What underlying factors contributed?
- What systemic issues were revealed?

## 6. AAR Timing Guidelines

| Event Type | AAR Timing | Duration |
|:-----------|:-----------|:---------|
| Minor project | Within 1 week of completion | 30 minutes |
| Major project | Within 2 weeks of completion | 1-2 hours |
| Incident/Near miss | Within 48-72 hours | 30-60 minutes |
| Emergency drill | Same day or next day | 30-60 minutes |
| Complex operation | Within 1 week | 1 hour |

---

## 7. Documentation and Filing

### 7.1 Required Documentation

- Completed AAR form
- Supporting documents (flight logs, incident reports, etc.)
- Action tracking records
- Lessons learned register entries

### 7.2 Filing Requirements

| Document | Location | Retention |
|:---------|:---------|:----------|
| AAR form | Project file or event file | 5 years |
| Action tracking | Corrective action system | Until closed + 3 years |
| Lessons learned | Lessons learned register | Permanent |

## 8. Responsibilities

| Role | Responsibility |
|:-----|:---------------|

| **Operations Manager** | Schedule AARs; facilitate or assign facilitator; track actions |
| **Project Lead** | Facilitate project AARs; implement project-related actions |
| **All Participants** | Participate openly; implement assigned actions |
